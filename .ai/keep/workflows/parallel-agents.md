# 並行作業ワークフロー

## 目的

複数のエージェントが git worktree 上で同時に実装しても、成果物が衝突せず、統合時に整合が取れる状態を維持します。

## 前提

- 統合担当は1名（人間またはメインセッションのAI）に固定する
- 各作業エージェントは自分の worktree の中だけを変更する
- エージェント間で参照できるのは **Gitで追跡されているファイルのみ**。会話履歴、セッションメモリ、`.ai/temp/` は共有されない

## Wave方式

依存関係のある作業を同時に走らせると、下流のエージェントが存在しない契約に対して実装してしまいます。作業は Wave（波）に分けます。

1. **契約Wave**: 全トラックが依存する型・スキーマ・インターフェースを先に確定させる。並列化しない
2. **実装Wave**: 契約が凍結された後、担当ディレクトリが重ならないトラックだけを並列で走らせる
3. **統合Wave**: 統合担当が全ブランチをマージし、結合部分を実装し、全体検証を行う
4. **レビューWave**: [第三者レビューワークフロー](third-party-review.md)を並列で走らせる

契約Waveの成果物を実装Wave中に変更してはいけません。変更が必要な場合は統合担当へ報告し、統合担当が判断します。

## 作業エージェントの手順

### 1. 開始時

- `AGENTS.md` と `docs/index.md` を読む
- 自分の担当ディレクトリを `AGENTS.md` の担当範囲表で確認する
- `git status` と `git log --oneline -5` で分岐元を確認する
- 作業ブランチが未作成の場合、`develop` から `feature/<内容>` を切る

### 2. 実装中

- 担当ディレクトリ外のファイルを変更しない
- 共有ファイル（`AGENTS.md` / `CLAUDE.md` / `README.md` / `Makefile` / `backend/pyproject.toml` / `.env.example` / `docs/index.md` / `.ai/keep/` 配下）を編集しない
- 依存ライブラリを追加したい場合は、追加せずに完了報告へ「必要な依存とその理由」を書く
- 担当外の不具合を発見した場合、直さずに完了報告の未解決事項へ書く

### 3. 完了時

- 自分の担当範囲のテスト・lint・型チェックを実行する
- 変更をコミットする（コミットは行ってよい。pushは統合担当の指示があるときだけ）
- [完了報告テンプレート](../templates/completion-report.md)に従って報告する
- 報告には必ず次を含める
  - 作成・変更したファイルの一覧
  - 実行した検証コマンドと結果（未実施は理由付きで明記）
  - 担当範囲外で必要になった変更の要望
  - 契約（共有型）に矛盾を見つけた場合はその内容

## 統合担当の手順

1. 各ブランチの完了報告を読み、担当範囲外の変更が混入していないか `git diff --stat` で確認する
2. `develop` へ順にマージする。衝突が出た場合、解決方針を記録する
3. 各エージェントから上がった共有ファイルの変更要望をまとめて反映する
4. 結合部分（トラック間をまたぐ配線）を実装する
5. 全体のテスト・lint・型チェック・ビルドを実行する
6. レビューWaveを起動する

## 衝突を減らすための約束

- 1ファイルを2トラックが編集する設計になった時点で、トラック分割が誤っている。分割し直すか、直列化する
- 新規ファイルの追加は衝突しないが、`__init__.py` への追記は衝突する。`__init__.py` は再エクスポートを持たせず空に保つ
- テストファイルは担当トラックごとにディレクトリを分ける

## 禁止事項

- 他トラックのブランチを直接変更しない
- `develop` や `main` へ直接コミットしない（統合担当を除く）
- 強制pushと履歴の書き換えを行わない
- 他エージェントのコミットを rebase / squash で消さない
