# ADR 0003: fixture 優先の開発方針

- Status: Accepted
- Date: 2026-08-28

## 背景

SerpApi の API キーを取得していない。また依頼書は「SerpApi を大量消費しないよう fixture mode を最初から実装する」ことを最優先機能としている。

## 決定

- `SERPAPI_MODE=fixture` を既定とし、**外部通信ゼロで全機能と全テストが動く**状態を常に維持する
- fixture は[SerpApi レスポンススキーマ](../serpapi-schema.md)に厳密に従って作成する
- `live` 実装は書くが、API キー未取得のため**未検証**として扱う
- fixture には「フル項目版」と「最小項目版」を混在させ、任意キー欠落時の耐性を検証する
- 未確認のスキーマ項目に依存する実装を書かない

## 理由

- fixture の品質がテストの品質を決める。実レスポンス形状と乖離すると live 移行時に破綻する
- 公式ドキュメントで確認できた構造のみに依存すれば、乖離の範囲を限定できる
- fixture が既定であれば、開発中に誤って API クレジットを消費する事故が起きない

## 結果

- API キー取得後、[SerpApi レスポンススキーマ](../serpapi-schema.md)の「live 移行時に再検証すべき項目」を実データで確認し、fixture を更新する必要がある
- `live` 実装のテストは、HTTP レイヤをモックした単体テストに留まる。実 API との結合は未検証として報告する
